## 1. Stack

| Concern | Choice | Why |
|---|---|---|
| Language | TypeScript, `strict` | One language for game, tooling, and Worker |
| Build | Vite | Fast, first-class static output, PWA plugin |
| Game runtime | Phaser (latest stable major at implementation time) | Scenes, tweens, texture atlases, input. Mature on Android Chrome. Its sound manager is off; the app owns audio (§7). |
| Parent UI | Svelte, mounted as a DOM overlay | Forms and dashboards are painful in canvas |
| Offline | `vite-plugin-pwa` (Workbox) | Precached app shell plus each room's assets |
| Storage | IndexedDB via `idb` | Structured progress and stroke replays. Larger quota than localStorage. |
| Validation | `zod` | Asset manifest, content files, and imported progress JSON are validated at load time |
| Unit tests | Vitest | Tracing scorer, scheduler, nav graph, schema |
| E2E | Playwright, Android phone and tablet viewport emulation, touch enabled | Smoke tests per room |
| Lint/format | ESLint (`typescript-eslint` strict), Prettier | |
| Hosting | Cloudflare Workers, static assets | Free tier, global edge, preview versions per PR |
| Auth | Cloudflare Access (family Google accounts) | Her likeness and our voices are not public |

There is no backend in M1–M3. The Worker serves static assets only.

## 3. Runtime flow

```
BootScene ──tap "Mulai"──▶ HouseScene ──tap room──▶ character walks (nav) ──arrive──▶ <Activity>Scene
     ▲                         │  ▲                                                    │
     │                         │  └──────────────── activity done / back ◀─────────────┘
     │                    session timer expires
     │                         ▼
     └──── next launch ── BedtimeScene (character sleeps; app idles on a calm screen)
```

- Activity scenes are **lazy-loaded**. Each room's atlas and audio sprite are fetched on first
  entry and cached by the service worker afterwards.
- The scheduler (§5) decides which item an activity serves next. Scenes never pick content
  themselves.
- Each scene emits domain events (`AttemptRecorded`, `ItemMastered`, `SessionEnded`) on a typed bus.
  Storage and rewards subscribe to them, so scenes stay unaware of persistence.

## 4. Tracing engine

### 4.1 Glyph model

Glyphs are **centerline strokes**, not font outlines. Each one is hand-authored in
`src/content/glyphs/*.json`:

```jsonc
{
  "id": "upper.A",
  "metrics": "cap",                 // cap | xheight | ascender | descender | digit | stroke
  "strokes": [
    { "path": "M 0.5 0 L 0.1 1" },  // SVG path subset (M/L/C/Q), unit box, y down
    { "path": "M 0.5 0 L 0.9 1" },
    { "path": "M 0.25 0.6 L 0.75 0.6" }
  ],
  "audio": { "name": "letter.name.A", "sound": "letter.sound.a" }
}
```

- Stroke order and direction follow Indonesian school handwriting practice (the "huruf sekolah"
  style).
- Single-storey `a` and `g`.
- At load, each stroke is flattened and **resampled at a fixed arc length** (N ≈ 64 points), so
  scoring does not depend on screen size.
- The same data drives the "Lihat" demo animation, the guide rendering, and scoring. No glyph
  images are needed.

### 4.2 Interaction modes

| Mode | Used for | Behaviour |
|---|---|---|
| **Follow** | T0, and step 2 of new glyphs | A "lead ball" sits at the stroke head. It advances only when her finger is within the corridor *ahead* of it, so she cannot go wrong, only stall. Best fit for age 3. The corridor is set in glyph heights, but never narrower on screen than a floor in millimetres (set by the spike), because glyphs on the phone are about 2.5× smaller than on the tablet. |
| **Score** | Steps 3–4 | She draws freely, and the finished stroke is scored as in §4.3 |

Input handling:
- `pointerType === 'pen'` (the Tab S10+ S Pen) is handled exactly like touch.
- `pointerType === 'mouse'` (laptops without touchscreens) forces Follow mode with the widest
  corridor. The attempt is stored as practice and skipped by the scheduler's box updates
  (PRD US-LAPTOP-02).
- Pointer Events. Only the **first** active `pointerId` counts, so extra fingers and palms are
  ignored.
- `touch-action: none` on the canvas.
- Points are smoothed with a short moving average before scoring.

### 4.3 Scoring a stroke (Score mode)

All distances are relative to glyph height `H`.

| Metric | Definition | Age-3 default |
|---|---|---|
| Start | Distance from first touch to stroke start | ≤ 0.15 H |
| Coverage | Fraction of path samples within corridor `w` of any user point | ≥ 0.70 |
| Off-path | Fraction of user points farther than `w` from the path | ≤ 0.35 |
| Direction | Projected arc-length progress is mostly monotonic (backtrack ≤ 0.1 of length) | Enforced from T2 on. Matters most for the c family (c o a d g q all start counterclockwise). |
| Corridor `w` | Tolerance band | 0.12 H (adaptive range 0.08–0.18) |

When a stroke passes, the drawn line **morphs onto the ideal path** and sparkles. A failed stroke
fades out, and the guide replays the demo for that stroke only.

### 4.4 Adaptive tolerance

For each level, keep a rolling window of the last 10 stroke results:
- Success rate above 85% → tighten `w` by 0.01.
- Success rate below 50% → loosen `w` by 0.01.
- `w` stays within the range above, and the parent setting can override it.

Tolerance changes are logged so the dashboard can show the trend.

### 4.5 Testing

- `tests/fixtures/strokes/` holds real recorded attempts (exported from the parent area): good,
  sloppy, reversed, and scribble.
- Each fixture is labelled with the expected verdict. The scorer must reproduce the verdicts, which
  guards against regressions when thresholds are tuned.

## 5. Scheduler (spaced repetition)

A 3-year-old plays irregularly, so intervals count **sessions, not days**.

- Every learnable item (`upper.A`, `num.4`, `syl.ma`, `count.5`) has a record:
  `{ box: 1..5, lastSeenSession, attempts, successes }`.
- Box intervals in sessions: `1, 2, 4, 8, 16`. Success promotes one box. Three misses in one
  session demote one box. They never reset to box 1.
- Picker order for each activity:
  1. Items due for review, at most 2 of every 3 slots.
  2. The next new item in curriculum order (her name's letters first).
  3. One **already-mastered** item as an easy win.
- A level unlocks when 80% of the previous level's items reach box ≥ 3.
- The House hub asks the scheduler which rooms have due items, and **Bubu** points at those.

## 6. Navigation (house hub)

- `assets/house/layout.json` (authored with the house art, see `ASSETS.md` §4) defines:
  - room polygons (tap areas)
  - a standing spot for each room
  - waypoints (doors, stair top and bottom) with edges
- Dijkstra over the waypoint graph, weighted by segment length (a few dozen nodes, so a linear scan
  beats a heap and A* is unnecessary; a room with two doors makes a loop where the fewest hops is not
  the shortest walk). The character walks the polyline at constant speed.
- **Isometric facing**: each segment's screen direction picks `fr` or `br` (toward or away from
  the viewer) plus a horizontal flip, which gives 4 directions from 2 drawn facings.
- **Depth sorting**: characters and props sort by feet y. `occluders` from `layout.json` are drawn
  above any character whose feet are above their `sortY`, so Theia walks *behind* railings and
  sofas correctly.
- Tapping a room while walking **retargets** the path from the current position.
- Arriving at the room plays the room greeting voice clip, then starts the activity scene.
- **Camera**:
  - **Overview**: the whole diorama. Default on the tablet and the laptops.
  - **On arrival**: a smooth zoom (about 600 ms) into the room's `focus` rect. The room fills the
    screen like one of the sticker-book scenes, then the activity starts. The storeys above the
    room fade out with the zoom, and a storey that is mostly faded does not catch taps.
  - **Leaving**: zooms back out. Until the activity scenes exist, a tap anywhere off her room
    leaves it (`HouseScene.onTap`).
  - **Phone** (the main device): the overview opens zoomed to the current room. Drag to pan with
    inertia. Tapping a room that is partly on screen pans to it, so she never needs to pinch.
    Pinch-out shows the whole house.
    - A screen counts as a phone when its shorter side is under 600 dp, Android's tablet
      breakpoint (`src/engine/camera/device.ts`).
    - The phone's hub view frames a room by its `focus` rect, with every storey shown. A tapped
      room is framed while she walks there, and the zoom on arrival then only fades the storeys.
      Leaving goes back to that framing, not to the whole house.
    - Panning never runs off the house: the view is clamped so the screen stays on the 1920 × 1200
      frame. A drag must pass the tap slop before it pans, so a tap stays a tap. A throw glides
      to a stop (time constant 325 ms), and a finger going down stops the glide.
    - A pinch zooms out no further than the whole house, and in no closer than the tightest room
      framing. A drag or pinch takes the view over at once, while a fade in progress finishes.
    - Every room keeps a tap area of at least 72 dp with the whole house shown on the phone.
      `house.layout` logs the smallest as `minTapDp`, and the E2E checks it on every device.

## 7. Audio engine

- One app-owned `AudioContext` (`src/engine/audio`), shared through the game services. Phaser's
  sound manager is off (`audio.noAudio`): its built-in unlock resumes the context at boot and on any
  gesture anywhere, which would race the Mulai tap. The tap on "Mulai" is the only unlock, and the
  voice queue only starts after it. Resuming after the app returns from the background is the audio
  engine's job.
- **Voice queue**: one voice clip at a time. A new instruction cancels pending praise, never the
  reverse. Background music ducks to −12 dB while a voice clip plays.
- Clips are referenced by **key** (`instr.tracing.follow`, `letter.name.A`). The narrator setting
  (Papa / Mama / alternate) picks the variant at runtime, with a fallback to the other parent if a
  clip is missing.
- **Speaker portrait**: each clip carries its speaker (`mama` | `papa`). In activity scenes the
  matching portrait shows while the clip plays. An `AnalyserNode` on the voice bus maps RMS
  loudness to the 3 `talk` frames (thresholds tuned once per voice), so lip-sync needs no
  authoring.
- Packaging: one audio sprite per room, in Opus (`.webm`). Pipeline in `AUDIO.md`.

## 8. Offline, hosting, and auth

### 8.1 PWA
- Web manifest: `display: fullscreen`, `orientation: landscape`, Indonesian name and short name,
  maskable icons.
- Workbox:
  - **Precache** the app shell, the house hub, and the boot audio.
  - **Runtime cache-first** for room bundles (`rooms/**`, `audio/rooms/**`): kept out of the
    precache and cached the first time she enters the room. `tools/build/budget.mjs` defines the
    prefixes for both the service worker and the size check; only `200` responses are cached.
- `navigator.storage.persist()` requested on first launch. The result is shown in the parent area.
- Updates use `registerType: 'prompt'`. The new version activates on the **next** cold start, never
  in the middle of a session.

### 8.2 Cloudflare Workers (static assets)

```jsonc
// wrangler.jsonc
{
  "name": "rumah-cici-theia",
  "compatibility_date": "2026-11-01",
  "routes": [{ "pattern": "rct.amns.my.id", "custom_domain": true }],
  "assets": {
    "directory": "./dist",
    "not_found_handling": "single-page-application"
  }
}
```

`public/_headers`:
- Hashed assets: `Cache-Control: public, max-age=31536000, immutable`
- `index.html`, `sw.js`, `manifest.webmanifest`: `no-cache`
- Strict CSP: `default-src 'self'`, `media-src 'self' blob:`, no third-party origins. Also
  `Permissions-Policy` that denies camera, mic, and geolocation.

### 8.3 Cloudflare Access
- An Access application covers `rct.amns.my.id`, and Access is enabled for the Worker's preview
  URLs (Worker → Settings → Domains & Routes). Production has no `workers.dev` route
  (`workers_dev: false`), so the custom domain is its only hostname. The policy allows the family Google accounts.
  Session duration: 1 month.
- Offline and on expired sessions, the service worker serves the cached shell, so she can always
  play. An update fetch that gets an Access redirect counts as "no update". The service worker
  never caches that redirect.
- A parent re-authenticates at `/masuk` to pick up new versions. The service worker answers every
  other navigation (including `/`) from the cached shell, so Access would never get to redirect.
  `/masuk` and Access's own `/cdn-cgi/` endpoints are on the navigation denylist
  (`src/platform/swRouting.ts`) and always reach the network.
- **Known gap: the macOS Safari Dock app.** It has no address bar, and it keeps its own cookies
  apart from Safari, so a parent cannot open `/masuk` inside it. Once its Access session expires
  it keeps playing the cached build but stops receiving updates. The fix is a "masuk lagi" button
  in the parent area that navigates to `/masuk` (issue #6). Until
  then, remove the Dock app and add it to the Dock again from Safari after logging in there.

### 8.4 Rollback
- Every deploy is a Worker version. Rollback with `wrangler rollback <version-id>`.
- Clients pick up the rollback on their next cold start, through the same update rules.
- Progress data has a schema version. IndexedDB migrations are **additive only**, so an older build
  can still read newer data, with unknown fields ignored.

## 9. CI/CD (GitHub Actions)

Every action is pinned by commit SHA.

```
lint ─▶ test ─▶ build ─▶ validate + e2e ─▶ SAST ─▶ quality-gate ─▶ deploy
```

| Stage | Contents |
|---|---|
| lint | `tsc --noEmit`, ESLint, Prettier check |
| test | Vitest with coverage. |
| build | `vite build`. Fails if the size budget (§10) is exceeded. Uploads `dist` for the next stages. |
| validate | `npm run validate` = `validate:design` + `validate:assets` (`tools/validate/`), against `contracts/`. Design: `tokens.json` (schema, contrast), `motion.json` (required moments, duration caps), `layouts/<screen-id>.json` (tap sizes per device, safe area, fixed HUD), keys cross-checked with the manifest, and the `ui/` lane rules. Assets: manifest schema and key families, image and frame sizes, drop zones, `layout.json` geometry and reachability, coloring-page closure, nothing unregistered. Unknown files and symlinks fail. Later: all audio keys referenced in content are present. |
| e2e | Playwright against the built `dist` (`vite preview`): tablet and phone (touch) and laptop (mouse) viewports, Chromium + WebKit. Runs next to validate. |
| SAST | Semgrep CE (`p/default`, `p/typescript`; CodeQL's licence excludes private repos without GitHub Code Security), `osv-scanner` on the lockfile |
| quality-gate | SonarQube Cloud. The gate blocks the pipeline. |
| deploy | `master`: `wrangler deploy` through the `production` environment (deployment branch: `master` only). PR: `wrangler versions upload` (preview URL, behind Access), off unless `vars.PREVIEW_DEPLOYS == 'enabled'`. |

Secrets:
- `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`: secrets of the `production` environment only.
  A `pull_request` run executes the PR's own workflow file and can read every repository secret, and
  a Cloudflare token that can upload versions can also deploy. The environment's branch policy keeps
  the token away from anything but `master`. The token itself is least privilege. Account: *Workers
  Scripts: Edit*, *Account Settings: Read*. Zone `amns.my.id`: *Workers Routes: Edit*.
- `SONAR_TOKEN`: repository secret, and a Dependabot secret for Dependabot PRs.

## 11. Observability (on-device only)

- `src/log` writes structured JSON entries
  (`{ ts, level, event, scene, sessionId, data }`) to an IndexedDB ring buffer of 2,000 entries.
- Uncaught errors and unhandled rejections are captured there with their stack traces.
- The parent area shows the log and can export it.
- Nothing leaves the device.
- Every uncaught error and unhandled rejection is fatal (except the benign `ResizeObserver loop`
  notice): the game is torn down at once, the recovery screen shows for about 2 s, and the app
  reloads to SCR-BOOT (PRD §7.5). One automatic reload per 30 s (`src/shell/recovery.ts`); a
  failure that comes back waits on the icon retry button. Once rooms exist, a scene error returns
  her to the House hub through OVL-RECOVER instead.

## 12. Data model (sketch)

```ts
type ItemId = `${'upper' | 'lower' | 'num' | 'stroke' | 'syl' | 'word' | 'count'}.${string}`;

interface ItemProgress {
  id: ItemId;
  box: 1 | 2 | 3 | 4 | 5;
  attempts: number;
  successes: number;
  lastSeenSession: number;
}

interface StrokeAttempt {          // kept for the newest 20 per item, for replay + fixtures
  itemId: ItemId;
  strokeIndex: number;
  points: Array<[x: number, y: number, t: number]>;
  verdict: 'pass' | 'fail';
  input: 'touch' | 'mouse';        // mouse attempts are practice-only: never change ItemProgress.box
  corridor: number;
  ts: string;
}

interface Settings {
  childName: string;
  sessionMinutes: number;          // default 10
  narrator: 'papa' | 'mama' | 'alternate';  // default 'mama'
  caseOrder: 'lower-first' | 'upper-first';  // default 'lower-first'
  corridorOverride?: number;
}

interface ProgressExport {
  schemaVersion: number;
  exportedAt: string;
  settings: Settings;
  items: ItemProgress[];
  attempts: StrokeAttempt[];
}
```
